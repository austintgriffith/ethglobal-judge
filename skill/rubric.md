# Rubric

Form criteria, each 1–10 (WOW starts at 5). Overall = rounded average.
Presentation comes only from the judge's notes / transcript; if none, write
"judge to score" and leave it out of the average.

## Technicality
- How hard is the problem, and how good is their approach?
- How much skill did the build need?
- Do they understand it, or is it an AI dump? Add a question that tests it.

## Originality
- New, or done before? Name similar projects/products if you know them.
- New problem, or a new solution to an old one?
- Common repeats score low unless the twist is real: AI agent wallet,
  prediction market, NFT ticketing, DAO voting, crowdfunding, tipping,
  generic DEX/lending fork.

## Practicality
- Works end to end, or a demo shell?
- Ready for its audience today?
- What does the user need first (wallet, extension, gas, bridge, KYC,
  hardware)? An app for non-crypto people that needs MetaMask is not practical.
- Distribution: does it only work with users/partners it can't realistically
  get (empty two-sided market, needs merchants or a protocol to adopt it)?

## UI / UX / DX
- Pleasant? Makes you want to use it? Friction removed (embedded wallets,
  gasless, passkeys, good defaults, clear errors, few clicks)?
- CLIs, SDKs and infra count. Judge DX: steps vs the old way, clear output,
  good defaults, helpful errors. Read their install steps and count them.
- If there's a live demo, look at it (background tab / screenshot). If not,
  say the score is from code only.

## WOW factor (5–10)
- Exceptional in some way? Name the one thing.
- Would you point at it in the finale? Nothing stands out = 5. Don't invent one.

## Demo quality
Real flow on a real chain, or clicking through mocks? Use the live demo,
video, or the judge's notes.

## Presentation quality
How good was the pitch. Judge's notes only.

## Buttons
- **Flag**: feels too good to be built at the event. Recommend when the rule
  check is SUSPECT or BROKEN.
- **Favorite**: shortlist. Only real standouts (top of room, WOW ≥ 8).

Always also report **Onchain reality** (real / partial / stubbed).

## HARD RULE: code written at the event
Libraries, frameworks and templates are fine. The team's own code must be
written during the event.
- Own code committed before the start = **BROKEN**.
- Dates can be faked. Also SUSPECT: one huge first commit with a finished
  app, files identical to an older repo of theirs, mature code with few
  commits, docs/package versions older than the event, commits seconds apart.
- Tracks for existing projects ("continuity" etc.): pre-existing code is
  allowed if disclosed. Score only the new work. Undisclosed = SUSPECT.
- Verdict goes at the top of the report: `Rule: OK / SUSPECT / BROKEN` + evidence.

## Score guide
9–10 finalist · 7–8 strong · 5–6 fine · 3–4 thin · 1–2 empty/fake.
See `calibration.md` for what each level looks like.

## Fallback questions (when nothing sharper fits)
- What is your stack? What was hardest?
- What's missing? What would you add with more time?
- What's next for the team? Did each of you learn something new?
